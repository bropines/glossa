# Развёртывание

Для тех, кто ставит Glossa на чужие компьютеры: тихая установка, куда
попадают файлы, подготовка настроек для пользователей, прокси, настройки,
которые сужают возможности Glossa, адреса, к которым она обращается, и
удаление. Обычному пользователю нужна [«Установка»](install.md). English:
[deployment.md](../deployment.md).

Названия пунктов меню и кнопок даны по русскому интерфейсу.

Glossa — бета, сделанная для одного пользователя. Эта страница описывает,
что на самом деле делают установщики и программа; набора возможностей для
управляемых рабочих мест она не обещает. Пакеты для Linux собираются и
проходят проверку «запускается», но на настоящем железе их ещё не
пробовали.

## Слоя политик нет

Общих для компьютера настроек, блокировки администратором, шаблонов
групповой политики и MDM нет. Все настройки лежат в `config.toml`
пользователя; пользователь может его править, а программа переписывает
файл, когда он что-то меняет в *Настройки*. Ничто из описанного на этой
странице нельзя навязать пользователю изнутри Glossa.

Что можно сделать: положить подготовленный `config.toml` до первого
запуска ([ниже](#подготовка-настроек-для-пользователей)), а остальное
обеспечить снаружи (межсетевой экран, контроль запуска программ, права
доступа к папке программы). Настроек, которые пользователь не смог бы
изменить, Glossa пока не предлагает.

## Тихая установка

В каждом выпуске есть файл `SHA256SUMS` с контрольной суммой каждого
файла. Подписи издателя у файлов пока нет: двоичные файлы для Windows
подписываются, только если выпуск собран с сертификатом (пока такого не
было), а приложение для macOS подписано локально (ad hoc) и не
нотаризовано. Поэтому в правилах контроля запуска программ нужно называть
путь или хеш, а не издателя.

### Windows

Установщик сделан в Inno Setup и принимает его обычные ключи. Нужна
Windows 10 или новее; установщик `x86_64` ставится и на ARM, а `arm64` —
только на ARM.

```bat
:: для текущего пользователя, без прав администратора
glossa-1.2.3-x86_64-windows-setup.exe /VERYSILENT /SUPPRESSMSGBOXES /CURRENTUSER

:: для всех пользователей, в Program Files (запускать с повышенными правами)
glossa-1.2.3-x86_64-windows-setup.exe /VERYSILENT /SUPPRESSMSGBOXES /ALLUSERS

:: по желанию: /DIR="D:\Apps\Glossa"  /TASKS="desktopicon,autostart"  /LOG="C:\Temp\glossa-setup.log"
```

| | для пользователя (`/CURRENTUSER`, по умолчанию) | для всех (`/ALLUSERS`) |
|---|---|---|
| папка программы | `%LOCALAPPDATA%\Programs\Glossa` | `%ProgramFiles%\Glossa` |
| ярлык в меню «Пуск» | пользовательский | общий |
| нужны повышенные права | нет | да |

Что установщик делает и чего не делает:

- **Задачи.** `desktopicon` добавляет ярлык на рабочий стол, `autostart`
  запускает Glossa в трее при входе. Обе выключены, пока не названы в
  `/TASKS`.
- **Автозапуск настраивается для пользователя.** Это значение `Glossa` в
  `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
  (`"<папка>\glossa.exe" --hidden`), записанное в куст той учётной записи,
  от имени которой работает установщик. Установка для всех, выполненная
  средством развёртывания от имени системной учётной записи, не включает
  автозапуск для тех, кто потом входит в систему. Чтобы Glossa запускалась
  у пользователя, создайте это значение в его кусте (скриптом входа или
  параметром групповой политики); тогда *Настройки → Основные → Запускать
  вместе с Windows* покажет его включённым.
- **Обновления.** Запустите новый установщик поверх старого. Тихое
  обновление закрывает Glossa, запущенную из целевой папки, сохраняет
  автозапуск как был и снова запускает Glossa в трее, если она была
  запущена.
- **Данные установщик не записывает.** Он не создаёт `config.toml`; это
  делает сама программа при первом запуске, в профиле пользователя.
- **Portable-режима не бывает.** Установщик не кладёт маркер `portable` и
  папку `data`, поэтому установленная копия всегда хранит данные в
  профиле.

Тихо удалить программу можно её деинсталлятором из папки программы; данные
пользователя он сохраняет (см. [«Удаление»](#удаление)):

```bat
"%LOCALAPPDATA%\Programs\Glossa\unins000.exe" /VERYSILENT
```

**Portable-архив** (`-windows-portable.zip`) — та же программа с файлом
`portable.txt` рядом: распакуйте его в папку, доступную пользователю для
записи, и настройки, история, модули и скачанное останутся в `data\` рядом
с `glossa.exe`. Запуск при входе, если пользователь его включит, по-прежнему
значение в его кусте реестра.

**winget и Scoop.** Glossa нет в общем репозитории winget, и бакета Scoop
у неё тоже нет. В каждом выпуске лежат манифесты, которыми можно
пользоваться напрямую ([Installing](../install.md#winget-and-scoop), на
английском).

### macOS

Файла `.pkg` нет. В выпуске есть `.dmg` и `.zip`, в каждом — `Glossa.app`;
в `.zip` есть ещё и `glossa-cli`. Для Apple silicon берите `arm64`
(macOS 11 или новее), для Intel — `x86_64` (macOS 10.15 или новее).
Установка из скрипта сводится к копированию:

```bash
hdiutil attach -nobrowse -quiet glossa-1.2.3-arm64-macos.dmg   # mounts as "/Volumes/Glossa 1.2.3"
ditto "/Volumes/Glossa 1.2.3/Glossa.app" /Applications/Glossa.app
hdiutil detach -quiet "/Volumes/Glossa 1.2.3"
xattr -dr com.apple.quarantine /Applications/Glossa.app        # only needed if the download was quarantined
```

- **Gatekeeper.** Приложение подписано локально (ad hoc) и не
  нотаризовано. Копию с атрибутом карантина (скачанную браузером) при
  первом запуске macOS отклоняет, пока пользователь не разрешит её в
  *Системные настройки → Конфиденциальность и безопасность* или пока
  атрибут не снят командой выше.
- **Разрешения выдаёт пользователь.** Для чтения выделенного текста нужен
  универсальный доступ, для снимка экрана — запись экрана, а режиму мыши
  может понадобиться мониторинг ввода. macOS привязывает разрешение к
  подписи программы, а локальная подпись у каждой сборки другая, поэтому
  после каждого обновления разрешения придётся выдавать заново. Выдавать их
  централизованно профилем конфиденциальности (PPPC) не пробовали, а
  отсутствие Developer ID не оставляет такому профилю постоянного
  идентификатора, на который можно сослаться.
- **Идентификатор пакета:** `io.github.bropines.glossa`.
- **Запуск при входе** — это агент запуска, который программа записывает,
  когда пользователь его включает: `~/Library/LaunchAgents/app.glossa.plist`.
- `glossa-cli` внутри приложения нет; если он нужен скриптам, скопируйте
  его из `.zip` в папку из `PATH`.

### Linux

На настоящем железе пока не пробовали. Пакеты собираются на Debian 12.

```bash
# Debian 12, Ubuntu 22.04 и новее
sudo DEBIAN_FRONTEND=noninteractive apt-get install -y ./glossa_1.2.3_amd64.deb
```

Пакет зависит от библиотек, с которыми собрана Glossa (GTK 3, ALSA,
OpenGL), рекомендует `tesseract-ocr` и библиотеку AppIndicator и
предлагает `python3`. Скриптов сопровождающего в нём нет, служб он не
устанавливает. Репозитория apt нет: новая версия — это новый `.deb`,
который нужно установить.

AppImage — один файл: положите его на место и сделайте исполняемым; нужен
FUSE или ключ `--appimage-extract-and-run`. `-linux-portable.tar.gz` —
portable-вариант (данные в `data/` рядом с программой); его `install.sh`
добавляет запись в меню только для текущего пользователя.

## Где лежат файлы

Программа хранит всё отдельно для каждого пользователя. Полная таблица
файлов — в [Configuration](../configuration.md#where-the-files-are) (на
английском).

| | Windows | macOS | Linux |
|---|---|---|---|
| настройки, история, пользовательские модули, темы (данные) | `%APPDATA%\Glossa` | `~/Library/Application Support/Glossa` | `~/.config/glossa` (`$XDG_CONFIG_HOME`) |
| журнал и кэш | `%LOCALAPPDATA%\Glossa` | `~/Library/Caches/Glossa` | `~/.cache/glossa` (`$XDG_CACHE_HOME`) |
| файлы, скачанные модулями: `models`, `runtimes`, `venvs` | `%LOCALAPPDATA%\Glossa` | `~/Library/Application Support/Glossa` | `~/.local/share/glossa` |
| файл настроек | `…\Glossa\config.toml` | `…/Glossa/config.toml` | `…/glossa/config.toml` |
| журнал | `%LOCALAPPDATA%\Glossa\glossa.log` | `~/Library/Caches/Glossa/glossa.log` | `~/.cache/glossa/glossa.log` |

В Windows папка данных находится в перемещаемом профиле, а скачанное — в
локальном, чтобы модели (они бывают больше гигабайта) не перемещались.

Всё в одну папку переносят две вещи:

- **`GLOSSA_HOME`** (переменная окружения; то же делает `--home DIR` в
  командной строке): папка данных — это указанная папка, кэш лежит в
  `cache` внутри неё, а скачанное — тоже внутри. Её читают и `glossa`, и
  `glossa-cli`. Пока она задана, Glossa не трогает запись автозапуска.
- **Portable-режим**: файл с именем `portable` или `portable.<что угодно>`
  либо папка `data` рядом с исполняемым файлом помещают всё в `data`
  рядом с ним. Папка программы должна быть доступна пользователю для
  записи, поэтому для `Program Files` это не подходит.

`glossa-cli config path` печатает используемую папку, `glossa-cli doctor` —
все папки.

## Подготовка настроек для пользователей

Положите `config.toml` в папку данных пользователя до первого запуска
Glossa (скриптом входа, шаблоном профиля, файловым шагом вашего средства
развёртывания). Все ключи необязательны, так что в файле нужно только то,
что должно отличаться от значений по умолчанию. Все ключи описаны в
[Configuration](../configuration.md) (на английском).

```toml
# %APPDATA%\Glossa\config.toml: a starting point, not a lock
[general]
ui_language = "en"
first_language = "de"
second_language = "en"
secret_storage = "system"      # keys go to the system keychain
show_welcome = true            # see below

[network.proxy]
mode = "manual"
scheme = "http"
host = "proxy.example.internal"
port = 3128

[modules]
trust_initialised = true       # see below
allow_native = false
allow_legacy_scripts = false

[server]
enabled = false
```

Что нужно знать о подготовленном файле:

- **Это отправная точка.** Когда Glossa сохраняет настройки, она
  переписывает файл целиком (комментарии и порядок ключей теряются,
  записываются все ключи), и пользователь может изменить что угодно.
- **Приветственный гид и первые подсказки** показываются, только когда
  файла настроек нет вовсе. При подготовленном файле `[general]
  show_welcome`, `show_tray_hint` и `[appearance] follow_system_theme`
  читаются как `false`, если файл их не задаёт. Задайте `show_welcome =
  true`, чтобы гид остался.
- **`[modules] trust_initialised`.** Файл настроек без этого ключа
  считается файлом из времён до появления одобрения модулей: при первом
  запуске Glossa одобряет каждый найденный установленный вручную модуль в
  том виде, как он объявлен в этот момент, и записывает ключ. Задайте
  `true` в подготовленном файле, чтобы любой присутствующий или
  добавленный позже модуль ждал одобрения пользователя. Не указывайте его,
  только если вы поставляете проверенные вами модули и хотите, чтобы они
  одобрялись без вопросов.
- **Не кладите в файл токен API управления.** Не указывайте `[server]
  token`, и каждая установка сгенерирует свой. Общий токен — это общий
  пароль.
- **Ключи.** Ключ API, записанный в файле, виден открытым текстом всем, кто
  может прочитать файл или общую папку, из которой его разворачивают. При
  `secret_storage = "system"` Glossa переносит его в связку ключей
  пользователя при следующем сохранении настроек; до тех пор он лежит в
  файле. Лучше пусть пользователи вводят свои ключи сами.
- **Файл, который не удалось прочитать,** переименовывается в
  `config.toml.broken-<время>`, а программа работает с настройками по
  умолчанию и выводит уведомление. Проверить подготовленный файл можно
  командой `glossa-cli --home <папка с ним> config show`.
- **Модули, темы и языковые пакеты** можно поставлять так же: в `modules/`,
  `themes/` и `locales/` папки данных или в папках рядом с программой, а
  они принадлежат установщику. Модуль в `<папка программы>\modules` (или в
  `/usr/share/glossa/modules`) считается поставляемым с Glossa и одобрения
  не требует, поэтому закройте эту папку от записи пользователями.
  Установка для пользователя в `%LOCALAPPDATA%\Programs` доступна ему для
  записи.

## Прокси и сертификаты

Задаются в *Настройки → Интернет* или в `[network.proxy]`:

| `mode` | что происходит |
|---|---|
| `"system"` (по умолчанию) | Переменные окружения `HTTPS_PROXY`, `ALL_PROXY`, `HTTP_PROXY` (берётся первая заданная, вместе с `NO_PROXY`). Если ни одна не задана, то в Windows — системный прокси пользователя (статический сервер и список исключений из *Свойств браузера*). |
| `"manual"` | `scheme` (`http`, `https`, `socks4`, `socks5`), `host`, `port` и, по желанию, `username` и `password`. |
| `"none"` | Прямые соединения. |

Ограничения, о которых стоит знать:

- **Автоматической настройки нет.** Автообнаружение прокси (WPAD) и
  скрипты PAC не реализованы. Компьютер с Windows, настроенный только
  скриптом, получит прямое соединение; используйте `manual`.
- **Системные настройки macOS и Linux не читаются.** Там `system` означает
  только переменные окружения, а у программы, запущенной из Dock или меню
  рабочего стола, их обычно нет. Используйте `manual`.
- **Проверка подлинности** — имя пользователя и пароль. Встроенная
  проверка подлинности прокси (NTLM, Kerberos) не реализована.
- **Петлевой адрес через прокси не ходит никогда**: `localhost`,
  `127.0.0.1`, `::1`.
- **Что следует настройке.** Каждый запрос, который Glossa делает сама,
  обращения модулей к хосту, скачивание файлов модулей и `uv`, когда он
  устанавливает пакеты Python. Модуль на Python, Java или модуль-процесс,
  открывающий собственные соединения, ей не следует.

**TLS.** Сертификаты проверяются по хранилищу доверенных сертификатов
операционной системы, поэтому корневой сертификат, который ваша
организация установила туда (например, для проверки TLS-трафика), Glossa
тоже считает доверенным. В Linux читаются обычные расположения и
`SSL_CERT_FILE` / `SSL_CERT_DIR`; если хранилище пусто, используется
встроенная копия корневых сертификатов Mozilla. Настройки, которая
отключала бы проверку сертификатов, нет. `glossa-cli doctor` печатает
используемый прокси и то, какое хранилище проверяется.

`[network] timeout_secs` (10) и `max_retries` (1) действуют на каждый
запрос к сервису; у ИИ-подключений в настройках есть собственное время
ожидания.

## Настройки, снижающие риск

Все они лежат в `config.toml` пользователя, и пользователь может их
менять ([Слоя политик нет](#слоя-политик-нет)).

| чтобы | задайте | примечания |
|---|---|---|
| Запретить нативные модули (разделяемые библиотеки, работающие внутри Glossa) | `[modules] allow_native = false` | По умолчанию `true`. |
| Запретить классические скрипты QTranslate `Service.js` | `[modules] allow_legacy_scripts = false` | По умолчанию `true`. Для связанной классической установки ещё `[classic] use_services = false`. |
| Чтобы каждый установленный вручную модуль ждал одобрения | `[modules] trust_initialised = true` в подготовленном файле | См. [выше](#подготовка-настроек-для-пользователей). Одобрения хранятся в `[modules.granted.<id>]`; удаление таблицы отзывает одобрение. |
| Не скачивать файлы модулей без щелчка | `[modules] auto_download_assets = false` | Значение по умолчанию. |
| Убрать сервис, встроенный или нет | `[modules] disabled = ["id", …]` | Действует на встроенные и поставляемые сервисы, ИИ-подключения и модули одинаково: указанный id не загружается вовсе. `glossa-cli services` перечисляет id. Список для всех онлайн-сервисов есть в [«Приватности»](privacy.md#работа-без-сети). |
| Не отправлять снимки областей экрана в Google Lens | `[ocr] provider = "windows-ocr"` (или `macos-vision`, `tesseract`) и `"lens"` в `[modules] disabled` | Одного выбора другого движка мало: при сбое выбранного движка распознавание [переходит](privacy.md#неочевидные-запросы) на Lens. |
| Отправлять каждый текст только одному сервису | `[services] fail_over = false` | Определение языка всё равно может уйти другому сервису; см. [«Приватность»](privacy.md#неочевидные-запросы). |
| Выключить API управления | `[server] enabled = false` | По умолчанию `true`, на `127.0.0.1:60828`. Вступает в силу при следующем запуске. `glossa-cli action …` после этого не сможет достучаться до запущенной программы. |
| Требовать токен и на маршрутах pot-app | `[server] pot_compat_without_token = false` | По умолчанию `true`. |
| Выключить службу D-Bus (Linux) | `[server] dbus = false` | По умолчанию `true`. Токена у неё нет. |
| Не хранить ключи в файле настроек | `[general] secret_storage = "system"` | По умолчанию `"file"`. Токен API управления остаётся в файле в любом случае. |
| Не вести историю | `[history] enabled = false` или `clear_on_exit = true` | Ещё `[general] save_contents_on_exit = false`: иначе текст главного окна остаётся в `config.toml`. |
| Не расширять журнал | не задавайте `GLOSSA_LOG` | Уровень по умолчанию записывает события и ошибки, но не переводимый текст. |

Glossa не просит прав администратора и в них не нуждается. Не запускайте
её с повышенными правами, чтобы добраться до окон с повышенными правами,
если это не нужно по-настоящему: тогда и её модули будут работать с
повышенными правами.

## Доступ к сети

**Входящих соединений нет.** Glossa слушает только `127.0.0.1:60828` (API
управления, если он не выключен и не перенесён через `[server] bind`).

**Исходящие** — всё по HTTPS на порт 443, если вы не настроили сервис
иначе, — делают `glossa` и `glossa-cli` (`glossa.exe`, `glossa-cli.exe`).
Разрешайте то, что нужно используемым функциям:

| функция | адреса |
|---|---|
| Google Translate, Google Dictionary, озвучивание Google | `clients5.google.com`, `translate.googleapis.com`, `translate.google.com` (или `translate.google.<домен>` при `[advanced] preferred_domain`) |
| Microsoft Translator | `www.bing.com`; с ключом `api.cognitive.microsofttranslator.com` |
| MyMemory | `api.mymemory.translated.net` |
| Yandex (без ключа), словарь Yandex | `translate.yandex.net` |
| Yandex Cloud (с ключом) | `translate.api.cloud.yandex.net` |
| DeepL (без ключа) | `oneshot-free.www.deepl.com` |
| DeepL API (с ключом) | `api-free.deepl.com`, `api.deepl.com` |
| Lara | `webapi.laratranslate.com` |
| ModernMT | `www.modernmt.com` |
| LibreTranslate, Lingva, DeepLX | сервер, заданный в настройках сервиса (по умолчанию `libretranslate.com`, `lingva.ml`, `127.0.0.1:1188`) |
| ИИ-подключения | базовый URL подключения: `api.openai.com`, `openrouter.ai`, `api.deepseek.com`, `generativelanguage.googleapis.com`, `api.groq.com`, `api.mistral.ai` или ваш собственный |
| Google Lens (распознавание текста) | `lensfrontend-pa.googleapis.com` |
| Словари | `www.multitran.com`, `api.lingvolive.com`, `www.oxfordlearnersdictionaries.com`, `en.wiktionary.org`, `dict.youdao.com`, `dic.academic.ru`, `translate.academic.ru`, `*.wikipedia.org`, `api.urbandictionary.com` |
| Файлы модуля PaddleOCR | `github.com`, `www.modelscope.cn` |
| Файлы модуля Local LLM | `github.com`, `huggingface.co` |
| Управляемый Python и `uv` | `github.com` |
| Пакеты Python | `pypi.org`, `files.pythonhosted.org` (запрашивает `uv`, отдельная программа в папке `runtimes`) |
| Другие модули | адреса из `[permissions] network` модуля, они показываются при его одобрении |
| Проверка обновлений (по запросу или раз в день, если включена) | `api.github.com` |

Скачивание с `github.com`, `huggingface.co` и `www.modelscope.cn`
отвечает перенаправлением на файловые серверы этих сайтов (для файлов
выпусков GitHub — адреса под `githubusercontent.com`), и они тоже должны
быть доступны. Эти имена принадлежат самим сайтам и могут измениться.

Кроме собственных программ Glossa, обращаться к сети могут: интерпретатор
Python и другие программы, которые запускают модули-процессы (они работают
из папок `runtimes`, `venvs` и `models` или из папки модуля), и `lens_scan`,
если для Lens используется chrome-lens-py.

В Glossa нет телеметрии, и в установленном виде она не делает запросов ни
при запуске, ни в фоне. Проверка обновлений обращается к `api.github.com`,
только когда пользователь нажимает *Проверить сейчас* или запускает
`glossa-cli update`, либо раз в день, если включён
`[updates] check_automatically`; по умолчанию она выключена
([«Приватность»](privacy.md#проверка-обновлений)).

## Обновление

Glossa сама не обновляется. Она может сообщить пользователю, что вышла
новая версия (*Настройки → Обновления*, `glossa-cli update`; ежедневная
проверка выключена, пока не задано `[updates] check_automatically = true`),
и тогда лишь открывает страницу выпуска в браузере. Разворачивайте новую
версию так же, как первую: установщик для Windows обновляет программу на
месте, в macOS замените `Glossa.app`, в Debian и Ubuntu установите новый
`.deb`. Настройки сохраняются, а файл настроек от старой версии продолжает
читаться. Выпуски и заметки к ним — на
[странице выпусков](https://github.com/bropines/glossa/releases); что
изменилось, написано в [журнале изменений](../../CHANGELOG.md) (на
английском).

Программы модулей (`paddle-ocr-v…`, `local-llm-v…`) выпускаются отдельно от
приложения и появляются в том же списке.

## Удаление

Шаги для каждой системы — в разделе
[«Полное удаление»](install.md#полное-удаление). Вкратце: программы
удаления убирают программу и оставляют данные пользователей, если не
сказать иначе:

| | убирает программа удаления | остаётся |
|---|---|---|
| Установщик для Windows | папку программы, ярлыки в меню «Пуск» и на рабочем столе, запись об удалении, значение автозапуска, если оно указывает на эту копию | `%APPDATA%\Glossa` и `%LOCALAPPDATA%\Glossa` каждого пользователя (интерактивное удаление предлагает удалить их для того, кто его запустил; тихое не удаляет никогда), записи Диспетчера учётных данных с именами `Glossa/…`, значения автозапуска в кустах других пользователей |
| macOS | ничего: программы удаления нет | всё, что перечислено в руководстве по установке |
| `.deb` | `/usr/bin/glossa`, `/usr/bin/glossa-cli`, `/usr/share/…` | у каждого пользователя `~/.config/glossa`, `~/.cache/glossa`, `~/.local/share/glossa`, `~/.config/autostart/glossa.desktop`, записи в связке ключей |

## Коротко

- **Телеметрии нет.** В Glossa нет ни аналитики, ни статистики
  использования, ни отправки отчётов о сбоях. Сбой записывается в
  локальный журнал и никуда не уходит.
- **Проверки обновлений нет, пока вы её не попросите.** Glossa спрашивает
  GitHub, вышла ли новая версия, только когда вы нажимаете *Проверить
  сейчас*, запускаете `glossa-cli update` или включаете ежедневную проверку
  (`[updates] check_automatically`, по умолчанию выключена). Сама она
  новую версию не скачивает и не устанавливает.
- **Ни учётной записи, ни сервера Glossa.** Между вами и сервисами
  перевода нет никакого сервиса самого проекта. Запросы идут прямо с вашего
  компьютера (через ваш прокси, если он задан) к выбранному сервису.
- **Переводчику нужно куда-то отправить текст.** Каждый онлайн-сервис
  получает текст, который переводит, а Google Lens — снимок области экрана,
  которую распознаёт. Что с этим делают сервисы, определяют их собственные
  политики конфиденциальности; Glossa на это не влияет. Большинство
  встроенных сервисов работают без ключа, через те же адреса, что и их
  сайты.
- **Само собой ничего не скачивается.** Файлы модулей, управляемый Python и
  пакеты Python загружаются только по кнопке *Скачать* (или когда включён
  `[modules] auto_download_assets` и модуль используется впервые).

## Что уходит с компьютера

Запрос делается, когда вы пользуетесь функцией, и к тому сервису, который
для неё выбран. В столбце «по умолчанию» отмечено, что включено в только
что установленной программе.

### Перевод

Текст для перевода, пара языков и, если сервис принимает, язык интерфейса.
Если задан ключ, он уходит только к своему сервису.

| сервис (id) | куда обращается | по умолчанию |
|---|---|---|
| Google Translate (`google`) | `clients5.google.com`, `translate.googleapis.com`, `translate.google.<домен>` (`[advanced] preferred_domain`, `com`, пока не изменён), по очереди | включён и выбран |
| Microsoft Translator (`bing`) | `www.bing.com`; со своим ключом `api.cognitive.microsofttranslator.com` | включён |
| MyMemory (`mymemory`) | `api.mymemory.translated.net` | включён |
| Yandex (`yandex-web`) | `translate.yandex.net` | включён |
| DeepL (`deepl-web`) | `oneshot-free.www.deepl.com` | включён |
| Lara (`lara`) | `webapi.laratranslate.com` | включён |
| ModernMT (`modernmt`) | `www.modernmt.com` | включён |
| DeepL API (`deepl`) | `api-free.deepl.com` или `api.deepl.com`, в зависимости от вида ключа | выключен (нужен ключ) |
| Yandex Cloud (`yandex`) | `translate.api.cloud.yandex.net` | выключен (нужен ключ) |
| LibreTranslate (`libretranslate`) | заданный вами сервер; пока не задан, `libretranslate.com` | выключен |
| Lingva (`lingva`) | заданный вами экземпляр; пока не задан, `lingva.ml`. Lingva — прокси перед Google Translate | выключен |
| DeepLX (`deeplx`) | заданный вами сервер; пока не задан, `127.0.0.1:1188`. Сам DeepLX пересылает запросы в DeepL | выключен |
| ИИ-подключения (`ai-…`, `openai`) | базовый URL, который вы ввели, или из пресета: `api.openai.com`, `openrouter.ai`, `api.deepseek.com`, `generativelanguage.googleapis.com`, `api.groq.com`, `api.mistral.ai`, либо локальная Ollama или LM Studio на `localhost` | пока вы не добавите, их нет |

«Включён» значит, что сервис есть в полосе сервисов. Спрашивается только
выбранный сервис, с двумя исключениями: если он не ответил и включён пункт
*Если сервис не ответил, пробовать следующий* (`[services] fail_over`,
по умолчанию включён), тот же текст получает следующий включённый сервис;
а при *Показывать все сервисы сразу* его получает каждый включённый
сервис.

ИИ-подключение получает текст внутри запроса к модели, вместе с вашей
подсказкой, стилем и глоссарием, если вы их задали, и названием модели.
Пресет OpenRouter, кроме того, отправляет заголовки `HTTP-Referer:
https://github.com/bropines/glossa` и `X-Title: Glossa`: по ним OpenRouter
узнаёт, какая программа обращается к нему. Их можно изменить или убрать в
поле *Extra headers* настроек подключения (подпись в интерфейсе пока
английская).

### Словари

Слово или фраза, которую вы ищете, и пара языков.

| словарь (id) | куда обращается |
|---|---|
| Google Dictionary (`google-dictionary`) | те же три адреса Google, что и у Google Translate |
| Yandex (`yandex-web`) | `translate.yandex.net` |
| Multitran (`multitran`) | `www.multitran.com` |
| ABBYY Lingvo Live (`lingvo-live`) | `api.lingvolive.com` |
| Oxford Learner's Dictionary (`oxford-learners`) | `www.oxfordlearnersdictionaries.com` |
| Wiktionary (`wiktionary`) | `en.wiktionary.org` |
| Youdao (`youdao`) | `dict.youdao.com` |
| Academic (`dic-academic`), Academic Translations (`translate-academic`) | `dic.academic.ru`, `translate.academic.ru` |
| Wikipedia (`wikipedia`) | `<язык>.wikipedia.org` |
| Urban Dictionary (`urban-dictionary`) | `api.urbandictionary.com` |
| Офлайн-словари (файлы StarDict, DSL, XDXF, TSV) | никуда: читаются с диска |

В только что установленной программе включены все онлайн-словари; спрашивается
тот, что выбран в окне словаря.

### Распознавание текста (OCR)

| движок (id) | что и куда уходит |
|---|---|
| Google Lens (`lens`), по умолчанию | снимок области в формате JPEG на `lensfrontend-pa.googleapis.com`, и язык перевода, если Lens просят ещё и перевести. В режиме *Авто* вместо этого используется запущенный на этом компьютере демон [chrome-lens-py](https://github.com/bropines/chrome-lens-py), если он есть; снимок Google он отправляет сам |
| Windows OCR, OneOCR, Apple Vision, Tesseract | ничего: работают на компьютере |
| Внешняя команда (`command-ocr`) | всё, что делает заданная вами команда |
| ИИ-подключения (модели с распознаванием изображений) | снимок, на выбранное вами для этого подключение |
| OCR-модули | то, что объявляет модуль: модуль PaddleOCR работает на компьютере, пример OCR.space отправляет снимок на `api.ocr.space`, пример Google Cloud Vision — на `vision.googleapis.com` |

После распознавания текст переводится как любой другой: самим Lens в том же
запросе или выбранным переводчиком (`[ocr] translate_with`). Ключ
`[ocr] save_image_dir` дополнительно сохраняет каждую снятую область в
папку; по умолчанию он не задан.

### Озвучивание

| голос (id) | что и куда уходит |
|---|---|
| Google (`google`), по умолчанию | текст, кусками до 200 символов, на `translate.google.<домен>`, `translate.googleapis.com` или `clients5.google.com` |
| Системные голоса (`system-tts`) | ничего: голоса Windows, `say` в macOS или espeak-ng в Linux |

### Модули

- **Модули на JavaScript** (встроенные сервисы выше — как раз такие модули)
  могут обращаться только к адресам, перечисленным в их `module.toml`, через
  собственный HTTP-клиент Glossa и ваши настройки прокси.
- **Модули на Python, Java и модули-процессы** — обычные программы,
  работающие от вашего имени. Их запросы через Glossa ограничены
  объявленными адресами, но ничто не мешает такой программе открыть
  собственные соединения или прочитать ваши файлы. То же относится и к
  **нативным модулям**, которые работают внутри Glossa.
- **Классические скрипты QTranslate и плагины pot-app** могут обращаться к
  любому адресу, как и в программах, откуда они пришли.
- Установленный вручную модуль не запустится, пока вы не одобрите то, что
  он просит в `module.toml`
  ([Permissions and trust](../modules/README.md#permissions-and-trust),
  на английском).

### Скачивания

Выполняются только по вашей просьбе (или при `[modules] auto_download_assets`).
Каждый файл перед использованием сверяется с SHA-256, записанным в модуле
или в Glossa.

| что | откуда |
|---|---|
| Программа модуля PaddleOCR | `github.com` (выпуски этого репозитория) |
| Модели PaddleOCR | `www.modelscope.cn` |
| Программа модуля Local LLM и llama.cpp | `github.com` (выпуски этого репозитория и llama.cpp) |
| Модель модуля Local LLM | `huggingface.co` |
| Управляемый Python и `uv` для модулей на Python | `github.com` (`astral-sh/python-build-standalone`, `astral-sh/uv`) |
| Пакеты Python, которые перечисляет модуль | `pypi.org` и адреса, с которых PyPI отдаёт файлы, либо индекс, названный в модуле; скачивает `uv` |
| Файлы других модулей | адреса из `[[assets]]` модуля, они показываются до того, как вы его одобрите |

Эти сайты отвечают перенаправлением на собственные файловые хранилища
(файлы выпусков GitHub, файловые серверы Hugging Face и ModelScope); Glossa
идёт по ним. Запрос на скачивание не содержит вашего текста, только то, что
есть в любом HTTP-запросе: ваш адрес и строку User-Agent Glossa.

### Проверка обновлений

Один запрос на `api.github.com` (список выпусков этого проекта), через ваш
прокси, если он задан. В нём нет ничего о вас, ваших настройках или
текстах; GitHub видит ваш адрес, как любой сайт. Запрос делается, когда вы
нажимаете *Проверить сейчас* в *Настройки → Обновления* или запускаете
`glossa-cli update`, и раз в день, вскоре после запуска, — только если
включён `[updates] check_automatically`. В только что установленной
программе он выключен. Ответ сохраняется в `update-check.json`. Если есть
новая версия, программа называет её, а страница выпуска открывается в
браузере по вашей просьбе; ничего не скачивается.

### Ссылки

Пункты *Справка*, *Поддержать проект*, *Открыть на GitHub* и «открыть в
браузере» передают адрес вашему браузеру. Сама Glossa для них запросов не
делает. Когда перевод открывается в браузере, текст попадает в этот адрес.

### API управления

[API управления](../control-api.md) слушает `127.0.0.1:60828` и включён по
умолчанию. Он принимает запросы с этого компьютера и сам никуда не
обращается. В Linux Glossa предлагает ещё и службу D-Bus на сеансовой шине.

## Неочевидные запросы

Что стоит знать, прежде чем полагаться на «я же выключил этот сервис».

- **Язык могут определять в другом сервисе.** Когда язык источника —
  *Автоопределение*, и при этом либо язык перевода автоматический, либо
  включено умное направление (по умолчанию включено), либо включено
  *Всегда определять язык*, текст сначала отправляется на определение
  языка. Сначала спрашивается выбранный сервис, если он умеет определять
  (умеют Google, Microsoft, Yandex и LibreTranslate; остальные и ИИ-подключения
  не умеют), затем остальные включённые, а **если не умеет ни один, то
  любой установленный сервис, который умеет**; на практике это Google
  Translate, даже если в списке он выключен. Чтобы этого не было, выберите
  язык источника сами и выключите умное направление либо уберите сервис
  совсем через `[modules] disabled` ([Работа без сети](#работа-без-сети)).
- **Распознавание текста переходит на другие движки.** Если выбранный
  движок отказал так, что другой мог бы справиться (не установлен, не
  настроен или нет сети), по очереди пробуются остальные: Google Lens,
  системный движок, Tesseract, внешняя команда. Поэтому при выбранном
  офлайн-движке сбой может отправить снимок в Google Lens. OneOCR и
  ИИ-подключения запасными не используются никогда. Этот переход не
  зависит от переключателя перехода к следующему сервису.
  `[modules] disabled = ["lens"]` убирает Lens.
- **Озвучивание тоже переходит на запасной сервис.** Если выбранный голос
  не сработал, используется любой другой сервис, который умеет
  озвучивать: если выбран системный голос и он не сработал, текст уйдёт
  в Google.
- **Встроенный пресет *Приватный* не работает офлайн.** Он переключает на
  Lingva и MyMemory, Wiktionary и Wikipedia и системный голос: сторон
  меньше и они другие, но текст всё равно покидает компьютер. Если вы не
  задали собственный экземпляр, Lingva — это публичный `lingva.ml`.
- **Переход к следующему сервису** отправляет тот же текст следующему
  включённому сервису, если первый не ответил. Выключите его в
  *Настройки → Сервисы*, если каждый текст должен уходить только одному
  сервису.

## Что хранится на компьютере

Всё лежит в папке данных и в папке кэша
([где они находятся](../configuration.md#where-the-files-are)):

| | Windows | macOS | Linux |
|---|---|---|---|
| данные | `%APPDATA%\Glossa` | `~/Library/Application Support/Glossa` | `~/.config/glossa` |
| кэш и журнал | `%LOCALAPPDATA%\Glossa` | `~/Library/Caches/Glossa` | `~/.cache/glossa` |
| файлы, скачанные модулями | `%LOCALAPPDATA%\Glossa` | `~/Library/Application Support/Glossa` | `~/.local/share/glossa` |

Portable-копия или копия, запущенная с `GLOSSA_HOME`, хранит всё в одной
папке.

| что | где | примечания |
|---|---|---|
| Настройки | `config.toml` (данные) | Обычный текст. Содержит токен API управления, он всегда остаётся в этом файле. |
| Ключи API, пароль прокси, токен демона Lens | по умолчанию в `config.toml` открытым текстом | Если в *Настройки → Основные → Ключи и приватность* выбрана системная связка ключей (`[general] secret_storage = "system"`), они лежат в Диспетчере учётных данных Windows (под именем `Glossa/…`), в связке «Вход» macOS (служба `Glossa`) или в Secret Service в Linux, а в файле на их месте стоит `@system-keychain`. Если связка ключей не отвечает, ключи остаются в файле. |
| История переводов | `history.json` (данные) | Каждый перевод, который показала настольная программа: исходный текст, переводы, сервис, языки, время. До `[history] max_entries` записей (5000). Обычный текст. `glossa-cli` и API управления добавляют записи только по запросу. |
| Поиск в словаре | `dictionary-history.json` (данные) | Слова, которые вы искали в окне словаря. |
| Текст главного окна | `[contents]` в `config.toml` | Поля исходного текста и перевода сохраняются между запусками, пока включён пункт *Сохранять содержимое при выходе* (по умолчанию включён). |
| Последняя проверка обновлений | `update-check.json` (данные) | Когда в последний раз спрашивали GitHub и что он ответил. Можно удалять. |
| Одобрения модулей | `[modules.granted]` в `config.toml` | Что вы одобрили для каждого модуля. |
| Снятые области экрана | папка из `[ocr] save_image_dir` | Только если вы её задали. |
| Журнал | `glossa.log` (кэш) | Дописывается, Glossa его не обрезает. В нём события, ошибки и сбои, но не переводимый вами текст; адреса запросов записываются без строки запроса. Всё, что выводит в консоль модуль на Python, Java или модуль-процесс, копируется в журнал, так что модуль может записать туда текст. `GLOSSA_LOG=debug` делает журнал подробнее. |
| Файлы модулей, управляемый Python, окружения Python | `models/`, `runtimes/`, `venvs/` | Скачанные программы и модели. |
| Прочие кэши | папка кэша | Кэши модулей, распакованные архивы `.potext`, скопированные библиотеки OneOCR, кэш загрузок `uv`. |
| Токен портала Wayland | `remote-desktop-token` (данные) | Только Linux. |
| Запись автозапуска | значение `Run` в реестре, `~/Library/LaunchAgents/app.glossa.plist` или `~/.config/autostart/glossa.desktop` | Только когда включён запуск при входе. |

На общем компьютере держите ключи в системной связке ключей, чтобы их
вообще не было в текстовом файле. Пресеты при экспорте ключей не содержат
никогда.

## Работа без сети

Glossa запускается и работает без сети; не работают только онлайн-сервисы.
Что работает на одном компьютере:

| для чего | что использовать |
|---|---|
| Перевод | ИИ-подключение к серверу моделей на этом компьютере (пресеты *Ollama* и *LM Studio*, `localhost`) или собственный сервер LibreTranslate. Модуль Local LLM есть в репозитории, но его программа ещё не выпущена. |
| Словари | Файлы StarDict, DSL, XDXF и текстовые с табуляцией: *Настройки → Сервисы → Словари → Добавить словарь…* |
| Распознавание текста | Windows OCR или OneOCR в Windows, Apple Vision в macOS, Tesseract где угодно или модуль PaddleOCR, когда его файлы скачаны: *Настройки → Распознавание текста → Сервис* |
| Озвучивание | Системные голоса: *Настройки → Сервисы → Озвучивание* |

Сам по себе такой выбор ничего не гарантирует из-за переходов на запасные
сервисы, о которых [сказано выше](#неочевидные-запросы). Чтобы точно
ничего не уходило к онлайн-сервисам, уберите их совсем. Список
`[modules] disabled` в `config.toml` — это id, которые не загружаются
вообще; он действует и на встроенные сервисы, и на модули:

```toml
[modules]
disabled = [
  "google", "google-dictionary", "bing", "mymemory", "lingva", "libretranslate",
  "deepl", "deeplx", "yandex", "lens",
  "yandex-web", "deepl-web", "lara", "modernmt", "multitran", "lingvo-live",
```

Правьте файл, пока Glossa не запущена. Потом `glossa-cli services` покажет,
что осталось. Добавьте `"openai"`, чтобы убрать и встроенный ИИ-переводчик;
подключения, которые вы добавили сами, перечисляются под своими id

появиться сервисы с новыми id, поэтому после обновления проверяйте список.
Надёжнее всего правило межсетевого экрана для `glossa` и `glossa-cli`
([адреса по функциям](deployment.md#доступ-к-сети)).

## Как удалить данные

| что удалить | как |
|---|---|
| История переводов | Кнопка *Очистить* в окне истории удаляет все записи, кроме избранных; отдельные записи удаляются из контекстного меню (*Удалить*). Чтобы удалить всё, завершите Glossa и удалите `history.json`. Пункт *Настройки → Основные → Очищать историю при выходе* очищает её при каждом выходе, а если выключить *Вести историю переводов*, записи вестись не будут. |
| Поиск в словаре | *Очистить историю* в окне словаря или удалить `dictionary-history.json`. |
| Сохранённый текст главного окна | Выключите *Сохранять содержимое при выходе* в меню главного окна или удалите `[contents]` из `config.toml`. |
| Ключи | Очистите поля в *Настройки → Сервисы* и примените. Если используется связка ключей, запись в ней тоже удалится; записи можно убрать и в Диспетчере учётных данных, в программе «Связка ключей» или в менеджере паролей рабочего стола (ищите *Glossa*). |
| Журнал и кэши | Завершите Glossa и удалите папку кэша. В Windows скачанные модулями файлы лежат в той же папке (`models`, `runtimes`, `venvs`); их можно скачать заново. |
| Файлы модуля | В настройках модуля — *Удалить файлы*; либо `glossa-cli assets remove ID` и `glossa-cli python remove`. |
| Всё | Завершите Glossa и удалите папки данных и кэша (и папку скачанных модулями файлов, где она отдельная). Остальное — запись автозапуска, записи в связке ключей и разрешения macOS — перечислено в разделе [«Полное удаление»](install.md#полное-удаление). |

`glossa-cli config path` печатает используемую папку данных, а `glossa-cli
doctor` — папку кэша и журнал.
